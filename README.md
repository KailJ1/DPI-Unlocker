# DPI-Unlocker

Программа создана с помощью нейросетей: они использовались для написания кода, поиска ошибок и доработки приложения.

Экспериментальная программа для Windows, которая помогает обходить некоторые виды сетевой DPI-фильтрации. Версия 1.0.6 от 21 октября 2026 года, Windows x64. Организация: Kriavpn. Сайт: https://kriavpn.ru.

DPI-Unlocker перехватывает пакеты на вашем компьютере через WinDivert и меняет способ передачи начала соединения. Это не VPN: программа не предоставляет другой внешний IP и не скрывает весь трафик от провайдера. Результат зависит от провайдера, адреса сервера и способа блокировки.

## Быстрый запуск

1. Полностью распакуйте ZIP в отдельную папку. Не запускайте программу из архива.
2. Откройте `DPI-Unlocker.exe` и подтвердите запрос администратора Windows. Права запрашиваются сразу при запуске.
3. Оставьте режим «Автоматически», включённые «Telegram автоматически» и «DNS через HTTPS». QUIC пока оставьте выключенным.
4. Нажмите «Включить». Права администратора нужны драйверу для перехвата пакетов.
5. Перезапустите проблемную страницу или приложение.

В раздаваемой автономной сборке .NET уже включён: отдельно устанавливать его не требуется. Нужна Windows 10/11 x64 с поддержкой .NET 9. ARM64, 32-битная Windows и Windows 7 этой сборкой не поддерживаются.

Без установленной службы закрытие окна останавливает движок. Кнопка «Отключить» также останавливает обработку. Не запускайте одновременно несколько программ, меняющих пакеты, например DPI-Unlocker и zapret/winws: они могут мешать друг другу.

## Автозапуск без окна

Нажмите «Установить службу» и подтвердите запрос администратора. Программа скопирует необходимые файлы в `C:\Program Files\DPI-Unlocker`, создаст и запустит службу `DPI-Unlocker` с автоматическим запуском при старте Windows. Служба работает от LocalSystem без окна и значка в трее.

После установки закрытие окна не останавливает службу. Кнопки «Включить» и «Отключить» управляют ею. «Проверить службу» показывает её состояние. Для применения других настроек выберите их в окне и снова нажмите «Установить службу»: это обновит файлы и перезапустит службу, текущие соединения могут переподключиться.

«Удалить службу» останавливает и удаляет регистрацию службы. Установленные файлы и журнал остаются; после удаления службы их можно удалить вручную. Системный прокси, DNS-адреса сетевого адаптера и настройки Happ программа не меняет. При включении DNS-модуля очищается системный DNS-кэш.

## Как это работает

### Сайты и HTTPS

DPI изучает первые пакеты соединения, в том числе имя сайта в TLS ClientHello. Программа может разделить начальные данные на несколько TCP-сегментов, отправить их в другом порядке или добавить ложный пакет. Сервер должен собрать исходный поток, а анализатор у провайдера может распознать его иначе.

Автоматический режим начинает с TCP overlap для видеосерверов googlevideo.com и TCP disorder для остальных адресов. При повторных отправках и ранних сбросах пробуются другие стратегии. Успешный ответ TLS запоминается в памяти до перезапуска. Он ещё не гарантирует, что страница, видео или загрузка завершатся.

В версии 1.0.5 исправлена отправка незавершённого ClientHello после таймаута сборки: начальный фрагмент теперь проходит через выбранную стратегию обхода. Основной поток входящих зашифрованных данных больше не проходит целиком через TCP-обработчик; он перехватывает ответы TLS handshake и сбросы. Это уменьшает нагрузку при загрузке видео. Отдельные правила перевода CDN-адресов по-прежнему обрабатывают трафик своих соединений.

Некоторые стратегии отправляют ложный TLS ClientHello с именем `www.google.com` и заведомо неподходящими параметрами TCP. Это дополнительный пакет для воздействия на DPI. Настоящие имя сайта и TLS-данные сохраняются; сертификат проверяет браузер или приложение. Корневые сертификаты программа не устанавливает.

HTTPS не расшифровывается и не заменяется другим шифрованием. Незашифрованный HTTP не становится зашифрованным. Обрабатываются начальные HTTP/TLS-соединения на TCP-портах 80, 443, 8443, 2053, 2083, 2087 и 2096. Поддерживаются IPv4 и базовый IPv6; некоторые сложные и неподдерживаемые пакеты пропускаются без изменений.

### DNS

Модуль перехватывает подходящие обычные DNS-запросы UDP/53 и отправляет их Cloudflare через HTTPS (DoH). Частные и локальные запросы пропускаются штатным путём. Адрес DNS в свойствах адаптера сохраняется. Если DoH недоступен, запрос может завершиться ошибкой; можно отключить «DNS через HTTPS» и повторить проверку. Собственный DoH браузера остаётся отдельным HTTPS-трафиком.

### Telegram

Поддерживаемые TCP-соединения Telegram перенаправляются в локальный мост, который передаёт MTProto через защищённый WebSocket. Неизвестные транспорты передаются напрямую. Это меняет внешний транспорт соединения, сохраняя шифрованное содержимое MTProto.

Для обработки транспортной обфускации используется AES-256-CTR: снимается и заново создаётся именно внешний слой обфускации, ключи которого находятся в транспортном заголовке. Шифрование самих сообщений MTProto программа не снимает. WebSocket защищён TLS с проверкой сертификата.

Мост использует адреса Telegram и может использовать сторонние Cloudflare-реле из публичного списка Flowseal/tg-ws-proxy, загружаемого с GitHub и кэшируемого локально. Следовательно, часть Telegram-трафика может идти через внешний ретранслятор; это не полностью локальный маршрут. Реле передаёт зашифрованное содержимое MTProto и видит сетевые метаданные соединения.

Сообщения и загрузки Telegram и голосовые звонки используют разные сетевые механизмы. **Звонки и групповые голосовые чаты Telegram в текущей сборке не исправлены.** WebSocket-мост не переносит голосовой UDP/STUN. На проверенном подключении голосовые серверы не отвечали; экспериментальные пробы не помогли и не включены в обычный запуск.

### Discord

Перед UDP discovery, принадлежащим процессу Discord, отправляются шесть сгенерированных ложных QUIC-пакетов, затем исходный запрос. Модуль определяет принадлежность локального порта процессу, поэтому не привязан к одному IP или региону. Звуковой поток не расшифровывается.

На проверенном подключении это восстановило RTC в автоматическом регионе Finland. Работа на другом провайдере, слышимость речи, видеосвязь и демонстрация экрана не гарантированы этим результатом.

### Альтернативные адреса серверов

Для нескольких конкретных IPv4 Instagram и WhatsApp программа заменяет адрес назначения на ранее проверенный альтернативный узел того же сервиса. Обратные пакеты преобразуются обратно. Для нескольких адресов Telegram Web применяются отдельные правила перенаправления. Googlevideo в версии 1.0.6 не перенаправляется на другой IP.

При HTTPS URL, SNI и TLS-поток сохраняются, сертификат проверяет клиент. Это ограниченные правила для конкретных адресов, а не универсальная замена серверов. Они могут устареть или не подходить для другой сети. Остальная TCP-обработка применяется без ручного списка доменов.

### QUIC

Отдельная опция QUIC экспериментальная и выключена по умолчанию. Она генерирует ложные QUIC v1 Initial перед настоящим UDP/443. Для корректного формата используются HKDF-SHA256, AES-128-GCM и защита заголовка по RFC 9001. Это криптография сгенерированного пробного пакета, а не замена шифрования браузера. Полная работа HTTP/3 не подтверждена.

## Что проверено и что ещё ограничено

| Возможность | Состояние на проверенном подключении |
| --- | --- |
| YouTube / Googlevideo / gstatic | Получались страницы, JS и диапазоны видео; весь SABR-поток, все CDN и HTTP/3 не подтверждены |
| Telegram: сообщения и файлы | Мост проходил повторные запросы; наблюдались соединения более пяти минут. Полное отсутствие переподключений не гарантируется |
| Telegram: звонки и голосовые чаты | Не исправлены |
| Discord: голос | Подключение RTC в автоматическом Finland подтверждено; результат зависит от сети |
| Instagram | Проверены HTML и статические ресурсы через альтернативные узлы; авторизованная лента и Reels не подтверждены |
| WhatsApp | Проверены HTML, CSS, JS и отдельные аватары; для части медиа были ошибки. Звонки не подтверждены |
| Steam | Скачивался установщик; стабильность реальной очереди игр не подтверждена |

Блокировка адреса или маршрута может происходить до TLS, и разбиение пакетов тогда не поможет. Программа не гарантирует доступ ко всем сервисам, а альтернативные CDN-адреса не являются универсальным решением.

## Если что-то не работает

1. Нажмите «Проверить службу» и убедитесь, что движок включён.
2. Используйте «Проверить сайты», затем проверьте само действие: воспроизведение, скачивание или вход. Ответ HTTPS сам по себе не доказывает полную работу сервиса.
3. Попробуйте режим «3 · TCP disorder» или «0 · TCP split» после остановки движка. При установленной службе выбранные настройки применяются повторной установкой службы.
4. При проблемах с DNS попробуйте отключить DoH. QUIC включайте отдельно как эксперимент.
5. Для сравнения нажмите «Отключить» и повторите действие. При установленной службе простого закрытия окна недостаточно.
6. Запишите сервис, действие, примерное время ошибки, провайдера и версию Windows.

## Журналы и данные

- Журнал службы: `C:\ProgramData\DPI-Unlocker\service.log`.
- Журнал окна: `gui.log` рядом с запускаемым exe, если папка доступна для записи.
- Кэш реле и служебные результаты: `%LOCALAPPDATA%\DPI-Unlocker` для соответствующей учётной записи; у службы это профиль LocalSystem.

Журналы могут содержать домены, IP-адреса и время соединений. Перед отправкой знакомым или публикацией проверьте их содержимое. Сборка для распространения не содержит журналов, персональных настроек Happ, сетевых трассировок и диагностических снимков.

## Исходники и сборка

Исходники приложения находятся в `src/DPI-Unlocker`. Сначала выполните `./build.ps1`: он скачивает WinDivert из официального релиза с проверкой SHA-256. После подготовки зависимостей автономную сборку для Windows x64 можно повторить командой:

```powershell
dotnet publish src/DPI-Unlocker/DPI-Unlocker.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:DebugType=None -p:DebugSymbols=false -o dist/DPI-Unlocker
```

Встроенные проверки запускаются командой `DPI-Unlocker.exe --self-test` и сохраняют `self-test.txt` рядом с exe. Они проверяют криптографические векторы и обработку пакетов; это не проверка всех сайтов и провайдеров.

Предыдущая история разработки сохранена в `docs/development-history.md` в исходном проекте. Диагностика звонков — в `docs/telegram-voice-2026-10-20.md`.

## Ошибки драйвера и сведения об издателе

При ошибке запуска используйте актуальную сборку. Start=4 у временной регистрации WinDivert не означает, что драйвер не работает. Для диагностики команда DPI-Unlocker.exe --driver-status создаёт driver-status.txt. Если Windows сообщает 1072, драйвер помечен на удаление; закройте другие пакетные движки и окно «Службы». Если состояние сохраняется, перезагрузите Windows и повторите запуск. Не отключайте BFE или защиту Windows.

В EXE записаны сведения Kriavpn, версия и авторские права. Кнопка «О программе» показывает сайт. Цифровая подпись Authenticode отсутствует: сертификат подписи кода не предоставлен, поэтому UAC может показывать неизвестного издателя.


Версия 1.0.5: исправлена ошибочная блокировка запуска по Start=4 временной регистрации WinDivert. Добавлена предварительная инициализация WFP и ограниченный повтор при FWP_E_ALREADY_EXISTS/FWP_E_IN_USE. Start=4 у загруженного временного драйвера сам по себе не доказывает поломку; запускайте актуальную версию до применения восстановительных скриптов.



## Изменения 1.0.6

- Подтверждённая стратегия запоминается отдельно для каждого домена и IP.
- Неудачный перебор не записывается как подтверждённая стратегия других соединений.
- Для разделённого TLS ClientHello учитывается SNI, обнаруженный в продолжении.
- Реальные TCP-сегменты обеих видеостратегий ограничены размером 1400 байт.
- Googlevideo CDN не подменяется. Проверены SABR POST и воспроизведение видео и Shorts; успех всех запросов и отсутствие всех задержек не гарантируются.
