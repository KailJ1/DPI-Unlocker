# Проверка aeza.ru и aeza.net — 21 октября 2026 (Обновлено)

## Итог проверки
**Сервис Aeza полностью доступен и функционирует.** Исходное предположение о сетевой блокировке или отказе TCP-маршрута опровергнуто детальными замерами сетевого стека и криптографической подсистемы Windows.

---

## Технические результаты

1. **Сетевой уровень (L3/L4 TCP)**:
   - DNS возвращает:
     - `aeza.ru` -> `95.181.177.124`
     - `aeza.net`, `my.aeza.net` -> `95.181.177.125`
   - TCP 3-way handshake (SYN -> SYN-ACK -> ACK) устанавливается за **4–25 мс** (`TcpTestSucceeded : True` на оба IP).
   - Фильтрации по IP или поломки маршрута со стороны провайдера нет.

2. **Работа службы DPI-Unlocker**:
   - Служба перехватывает пакет ClientHello и применяет стратегию обхода:
     ```log
     HELLO aeza.ru ip=95.181.177.124 bytes=454 sniOffset=131 strategy=3
     TLS_REPLY aeza.ru strategy=3 (ответ TLS получен)
     ```
   - TLS-ответ (`ServerHello`, `ChangeCipherSpec`, `Application Data`) поступает от сервера мгновенно (в течение 0.02 с).

3. **Причина первичного зависания системного `curl.exe`**:
   - В Windows утилита `curl.exe` скомпилирована с движком **Windows SChannel**.
   - Сертификат `*.aeza.net` / `aeza.ru` выпущен греческим удостоверяющим центром **HARICA** (`CN=HARICA DV TLS RSA`).
   - Сервер Aeza при TLS 1.3 хэндшейке отдаёт только конечный (leaf) сертификат без промежуточного сертификата УЦ.
   - SChannel по умолчанию выполняет строгую проверку списков отзыва (CRL/OCSP) по адресам `http://crl.harica.gr/HARICA-DV-TLS-Sub-R1.crl`.
   - При отсутствии промежуточного сертификата в локальном хранилище системный CryptoAPI уходил в тайм-аут с кодом:
     ```
     0x80092013 (CRYPT_E_REVOCATION_OFFLINE) — Функция отзыва не смогла произвести проверку отзыва для сертификата, т.к. сервер отзыва находился в автономном режиме.
     ```
   - При этом `curl.exe` останавливался на шаге `ALPN: curl offers http/1.1`, создавая иллюзию «зависания до TLS/SNI».
   - **Подтверждение:** `curl.exe --ssl-no-revoke https://aeza.ru/` соединяется за **0.07 с**.

4. **Устранение задержки проверки сертификата**:
   - Промежуточный сертификат HARICA (`http://crt.harica.gr/HARICA-DV-TLS-Sub-R1.cer`) добавлен в хранилище доверенных промежуточных центров:
     ```powershell
     certutil -user -addstore CA HARICA-DV-TLS-Sub-R1.cer
     ```
   - Проверка цепочки `certutil -verify aeza.cer` завершается успешно: `Проверка цепочки сертификатов пройдена успешно! (код 0)`.
   - После этого стандартный `curl.exe https://aeza.ru/` без дополнительных флагов отвечает за **0.3 с**.

5. **Защита от ботов (Bot Protection Challenge)**:
   - Сервер `aeza.ru` при первом GET-запросе возвращает `HTTP 307 Temporary Redirect` и выдаёт куку:
     `Set-Cookie: bp_chl=...; path=/; HttpOnly; Secure`.
   - Клиент, сохраняющий куку (браузер или HTTP-клиент), при повторном запросе получает **`HTTP 200 OK`** и полную страницу Next.js (140 Кб).
   - Личный кабинет `https://my.aeza.net/` отдаёт статус **`HTTP 200 OK`** напрямую за **0.2 с**.
